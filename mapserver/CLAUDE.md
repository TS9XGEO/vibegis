# mapserver

Renders WMS/WMTS/OGC-API from PostGIS and from rasters in `data/`. Mounted read-only
into the container; `data/` is also the drop-zone Dagster's `raw_vectors` asset reads.

## Mapfile layout

`mapfiles/vibegis.map` is the root (`MS_MAPFILE`). It holds the `MAP` header —
projection, `OUTPUTFORMAT` png/jpeg, `SHAPEPATH /data`, `FONTSET`, `SYMBOL`s — a few
hand-written layers (`poi`, `dem`, `adm2_overview`, `adm2_detail`), then at the bottom:

```
INCLUDE "osm-layers.map"    hand-written OSM layers, classified
INCLUDE "uploads.map"       GENERATED by upload-api — do not hand-edit
```

`layer_config.json` is also machine-written (per-layer classification state, owned by
upload-api). Both show up as dirty diffs during normal use; that is expected.

## Rules

- **No `password=` in `CONNECTION`.** libpq takes it from `PGPASSWORD`, set on the
  container by compose from `.env`. These files are in git.
- **Every `CLASS` needs a `NAME`** — that is what makes it appear in
  `GetLegendGraphic`. A nameless class renders but is invisible in the legend.
- **Colour convention** in `osm-layers.map` follows CORINE Land Cover, darkened for a
  night basemap: vegetation green, agriculture olive, urban fabric red, commercial
  orange-red, industry violet, extraction plum, water blue, bare ground grey.
- **Compute in SQL, colour in the mapfile.** A `CLASS` with a complicated `EXPRESSION`
  usually means the rule belongs in a derived PostGIS column, where it is indexable and
  evaluated once instead of per tile request. See `docs/classification.md`.
- **`PROCESSING "CLOSE_CONNECTION=DEFER"`** on every PostGIS layer — it keeps the
  connection open across layers in one request. Keep it on new layers.
- A layer upload-api created (in `uploads.map`) is cached automatically —
  `generate_mapproxy_config()` there gives every such layer its own cache in
  `mapproxy/mapproxy.yaml`, which is machine-written now, same as `uploads.map` and
  `layer_config.json` (don't hand-edit it while the stack is up; it's overwritten on
  the next layer change). A layer added here by hand still needs manual wiring: add it
  to `mapproxy/mapproxy.yaml` and to `HAND_AUTHORED_CACHED_LAYERS` in
  `frontend-app/src/wms.ts`.

## Applying changes

MapServer re-reads the mapfile on each request, so an edit is live immediately — that
is what lets upload-api publish by appending. If a change doesn't show,
`docker compose restart mapserver` and check `docker compose logs -f mapserver`
(`MS_DEBUGLEVEL` is 1, errors go to stderr).

Quick check:

```bash
curl -s "http://localhost:8080/mapserver?SERVICE=WMS&VERSION=1.3.0&REQUEST=GetCapabilities" \
  | grep -o '<Name>[^<]*</Name>'
```
